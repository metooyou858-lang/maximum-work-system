# MAXIMUM — правила для исполнителя

Этот файл — короткий обязательный вход. Постоянная память проекта находится в `docs/`, чтобы ею одинаково пользовались Codex, другие исполнители и владелец.

## Непереговорные правила

- ОБЯЗАН ДОВОДИТЬ СОГЛАСОВАННЫЕ ДЕЙСТВИЯ ДО ПРОВЕРЕННОГО РЕЗУЛЬТАТА: НЕ ОСТАНАВЛИВАТЬСЯ НА ПОЛУПУТИ, НЕ ПЕРЕКЛАДЫВАТЬ ТЕХНИЧЕСКИЕ ШАГИ НА ВЛАДЕЛЬЦА И НЕ ВЫДАВАТЬ ПОДГОТОВКУ ЗА ГОТОВУЮ РАБОТУ.
- Если владелец не может пройти рабочий сценарий (например, войти в систему), задача не завершена, пока этот конкретный сценарий не пройден фактически в опубликованном интерфейсе. Проверки базы, API, health-маршрута или кода сами по себе не заменяют результат для владельца. Повторять диагностику и исправления столько, сколько нужно, до подтверждённого прохождения сценария или до конкретного внешнего блокера.
- После каждого исправления обязательно проверить затронутый пользовательский путь целиком в опубликованном интерфейсе. Не сообщать о готовности по косвенным техническим признакам; передать результат только после видимого подтверждения сценария.
- ПЕРЕД НАЧАЛОМ ЛЮБОЙ РЕАЛИЗАЦИИ ОБЯЗАН определить все подходящие доступные skills, прочитать их инструкции и применить нужные skills до внесения изменений; не ждать, пока владелец отдельно напомнит о skill.
- Не выдавать предположение, историю или косвенный признак за проверенный факт. Если что-то не проверено, прямо назвать ограничение.
- Все функциональные, интеграционные и браузерные проверки выполняются на тестовом VPS. Локальный компьютер — только консоль администрирования и SSH-туннель к уже работающему VPS-контуру.
- Реальные сотрудники, email, геопозиция, рабочие отчёты и выгрузки запрещены: используются только синтетические данные до отдельного рабочего запуска.
- Не хранить секреты в исходниках, SQLite, документации, командах или сообщениях.
- При работе с Яндекс API не перезагружать карту сериями: `429` ограничивает частоту запросов и временно ломает загрузку JS API для ключа/IP; проверять один раз и использовать кэш/задержку.
- Для Яндекс API ключ JavaScript API передаётся только в `YANDEX_MAPS_API_KEY`, а ключ геокодера — только в `YANDEX_GEOCODER_API_KEY`; маршруты `/map-config` и `/geocode` не должны использовать переменные наоборот.
- Не расширять бизнес-логику, поля, роли и UX-сценарии без прямого решения владельца.
- Править файлы через `apply_patch`; кириллицу сохранять в UTF-8.
- После переноса SQLite-схемы на PostgreSQL проверять `column_default` у всех генерируемых `id`: `BIGINT PRIMARY KEY` не создаёт последовательность и ломает вставки без явного идентификатора.

## Коротко о текущем контуре

- VPS: `89.125.214.188:22`, администратор `maximum-admin`, доступ только по защищённому ключу; перед подключением читать серверную инструкцию.
- На VPS развёрнут только `maximum-work.service` (4174), Caddy публикует рабочий контур по HTTPS, PostgreSQL-база общая; старый `maximum.service` отключён.
- Карта: Яндекс Карты. Ключ хранится только в закрытом окружении VPS; на VPS проверены загрузка карты, выбор маркера, сохранение координат и повторное открытие точки.
- Рабочая карточка сотрудника восстановлена и проверена на VPS. Поля: ФИО, email, телефон, фото, дата рождения, одежда и обувь. Создание пока формирует только `pending_activation`; логин и приглашение сотрудника ещё не реализованы.
- Продукт: учёт работ, сотрудников и оборудования MAXIMUM. Главный путь — объект → личное прибытие с геопроверкой → личный отчёт → просмотр руководителем.

## Обновление памяти

Неочевидную ошибку, подтверждённое архитектурное решение или изменённый порядок работы записывать в подходящий документ `docs/`. В `AGENTS.md` оставлять только обязательные правила и ссылки.
