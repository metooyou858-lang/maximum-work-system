## Демонстрация сценария — 28.09.2026

- **Подтверждено пользователем:** на ближайшей встрече показ целиком с телефона; внешний вид пока не предмет согласования. Нужен сценарий: назначенный объект → прибытие с геопроверкой → личный отчёт → просмотр результата руководителем.
- **Последнее уточнение пользователя, приоритет над прежними протоколами:** повторная геопроверка при сдаче отчёта убрана; фиксируются факт принятия и время сдачи. Фактическое убытие и длительность присутствия в этой итерации не фиксируются и не вычисляются из времени отчёта.
- **Рабочее направление для демонстрации:** отчёт доступен после успешного прибытия; одна отметка и один отчёт на проход сценария. «Новый показ» создаёт отдельный проход без удаления старого. Форма отчёта временная: вид работ, объём, подходящая единица, параметры, необязательный комментарий. Это не окончательная форма заказчика.
- **Архитектура демонстрации:** `public/` — общий интерфейс; `server.mjs` — локальный Node.js 24 + SQLite без npm-зависимостей, серверные время, состояния и проверка роли; `phone-demo/` — отдельная статическая версия для одного телефона, данные и время берутся из браузера. Она не синхронизируется между устройствами, не является рабочей базой и не использует VPS. Серверная и телефонная версии не должны выдаваться за одну развёрнутую систему.
- **Тестовые данные:** геопозиция только синтетическая, ситуации выбираются в интерфейсе; настоящие координаты телефона не запрашиваются. Радиус 150 м и требование `расстояние + погрешность <= радиус` — демонстрационные настройки, не согласованный регламент. Сбой геопозиции не означает нахождение вне объекта.
- Источник телефонной версии — `public/` и конфигурация из `server.mjs`; обновлять через `node ops/prepare-phone-demo.mjs`, затем проверять и публиковать `phone-demo`. Не включать документы, `data/`, секреты и файлы VPS в репозиторий публикации. Сайт закрытый, для владельца аккаунта.
- **Проверки:** `npm test` проверяет серверный сценарий и перезапуск базы; `tests/browser.mjs` проверяет обе версии в Chromium. В этой Windows-песочнице дочерний процесс тест-раннера даёт `spawn EPERM`, поэтому используется `--test-isolation=none`; браузер запускается с обычным разрешением на локальную проверку, без изменения защиты системы.
- **Неочевидная ошибка UI:** общий `button:hover` перекрывал фон выбранной роли, оставляя белый текст на светлом фоне. Для `button[aria-pressed="true"]:hover` задан отдельный фон; проверять выбранную роль также после нажатия/наведения.
- **Неочевидная ошибка запуска кабинета:** первый запрос кабинета может зависнуть из-за недоступного или устаревшего локального сервера. Все стартовые запросы кабинета имеют таймаут 10 секунд, сообщают понятную причину и автоматически обновляют просроченный сеанс; после изменения `server.mjs` локальный Node-сервер нужно перезапускать.
- **Публикация Sites на этом Windows-компьютере:** штатная упаковка не завершилась, отдельный `prepare-site-build.cjs` дал `EIO, Access is denied` при подготовке каталога. Исходники успешно отправлены штатным `site-workflow.mjs`; для этой версии использован разрешённый fallback — сборка хостингом без локального архива. Не считать неуспешную упаковку неуспешной отправкой исходников и не создавать новый Site при повторе. Идентификатор существующего Site — в `phone-demo/.openai/hosting.json`.
