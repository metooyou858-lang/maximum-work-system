# Зафиксированные рабочие решения

Сюда попадают правила процесса и архитектурные решения, которые нельзя терять между сессиями. Новое подтверждённое решение добавляется сразу после обсуждения.

## 01.10.2026 — рабочая среда и поставка

- Рабочая папка на ноутбуке — источник файлов проекта.
- Локальный запуск приложения не используется для разработки, приёмки или показа.
- После завершённого этапа изменения разворачиваются на тестовый VPS.
- Функциональные, интеграционные и браузерные проверки выполняются на VPS.
- Этап считается завершённым только после проверки результата на VPS.

## 01.10.2026 — целевая структура продукта

- Целевой продукт — одно приложение, одна авторизация и одна база данных.
- Новые отдельные демонстрационные или рабочие контуры без отдельного решения владельца не создавать.
- Уже работающие функции проверять после каждого следующего изменения.

## 01.10.2026 — единый адрес тестового контура

- Основной публичный адрес — `https://89-125-214-188.sslip.io`.
- Рабочий кабинет руководителя доступен по пути `/manager/` этого же домена.
- Старый отдельный домен `work-89-125-214-188.sslip.io` больше не используется для работы.
- Данные рабочего кабинета и основного сценария находятся в одной тестовой SQLite-базе; отдельный файл `work.sqlite` больше не является источником данных.

## 01.10.2026 — единая стартовая авторизация

- Демонстрационная страница на корневом пути `/` удаляется из основного входа.
- Корневой адрес основного домена перенаправляет на единую стартовую страницу авторизации `/manager/`.
- Эта страница является общей точкой входа для руководителя и сотрудника; доступный раздел после входа определяется учётной записью.
- Полноценная активация и рабочий кабинет сотрудника остаются отдельным незавершённым пунктом до реализации серверного сценария сотрудника.
- Адрес объекта сохраняется только после результата геокодера Яндекс; ручной ввод или произвольная точка без подтверждения запрещены.
- Стартовый центр карты — Хабаровск (`48.4827, 135.0721`).

## 01.10.2026 — ведение документации

- Реализованное и развернутое отмечается в `docs/DELIVERY_STATUS.md`.
- Подтверждённые правила и архитектурные решения записываются в этот документ.
- Каждая нерешённая ошибка или блокер записывается в `docs/ACTIVE_ISSUES.md` с указанием проверки и следующего действия.
- После устранения проблемы её удаляют из `ACTIVE_ISSUES.md`; история изменения остаётся в Git.

## 01.10.2026 — разделение ключей Яндекс API

- Ключ JavaScript API используется только для загрузки карты (`YANDEX_MAPS_API_KEY`).
- Ключ API Геокодера используется только серверным маршрутом подтверждения адреса (`YANDEX_GEOCODER_API_KEY`).
- Перед завершением этапа проверяются оба направления: карта в браузере и геокодирование синтетического адреса на VPS.
