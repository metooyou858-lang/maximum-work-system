# Технические решения

## Карта

- Поставщик для тестового и рабочего контура — Яндекс Карты; зарубежные картографические сервисы не использовать.
- Используется JS API Яндекс Карт v3. Ключ передаётся только как `YANDEX_MAPS_API_KEY` в окружении сервера; не хранится в исходниках или SQLite и не показывается после сохранения.
- На 01.10.2026 новый ключ активен, тариф в кабинете показывает 100 запросов в сутки, а разрешённый Referer — `89-125-214-188.sslip.io`. Ключ задан только в закрытом окружении VPS. На VPS в браузере проверены загрузка карты, выбор маркера, сохранение координат и повторное открытие точки.
- Приёмка карты: HTTPS на VPS → разрешённый Referer → загрузка карты → постановка маркера → сохранение координат и радиуса → повторное открытие объекта.

## Приложение и данные

- `server.mjs` использует Node.js 24 и SQLite без npm-зависимостей; серверное время, состояния и роль проверяются на сервере.
- `work-server.mjs` хранит только хеши паролей и отдельные серверные сессии `work_sessions`; рабочий кабинет опубликован на общем домене `/manager/` и использует общую SQLite-базу с основным сервисом. Реальные данные в нём не использовать.
- Тестовые данные всегда синтетические. Демонстрационный радиус 150 м и условие `расстояние + погрешность <= радиус` не являются утверждённым регламентом.

## Известные технические факты

- Старый локальный запуск карты завершался ошибкой загрузки; это не диагностика ключа и не доказательство работоспособности интеграции.
- `Referrer-Policy: no-referrer` блокирует авторизацию JS API по разрешённому домену. Для кабинета используется `strict-origin-when-cross-origin`.
- Образ VPS ранее имел masked `ufw.service`; после изменений UFW проверять переживание реальной перезагрузки.
- В Ubuntu параметры SSH берутся из первого подходящего файла `sshd_config.d`; обязательные ограничения задавать в `00-maximum-access.conf` и проверять через `sshd -T`.
